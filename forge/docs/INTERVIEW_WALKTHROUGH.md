# Interview walkthrough

Ten minutes. Run `make interview` once before the conversation so the beats are green. Open `ARCHITECTURE.md` and the UI (`make up`, http://127.0.0.1:8095) side by side. `make interview` writes `reports/interview.md`.

The unprotected pane is a preview. Say that early. Do not imply the demo executed a denied call.

---

## 0. The problem (45 seconds)

**Say:** "An agent tool call is a small program the model picked. The failure mode I care about is not a clever exploit. It is a path with `..`, an `import os`, a shell string, or a loop. Forge is the function in front of that call. It either refuses before a process exists, or it runs the snippet in a short-lived interpreter with limits and an audit record."

**Show:** the trust-boundary diagram in `ARCHITECTURE.md`. Point at TB1 (caller to guard), TB2 (guard to child), TB4 (child to the host, blocked).

---

## 1. Lifecycle (60 seconds)

**Say:** "Every call takes the same path. Preview, then the hard guard, then either a file tool or a child process. The child sets rlimits, installs an audit hook, and repeats the AST gate. The parent writes one hash-chained line."

**Show:** the lifecycle flowchart. Then the happy-path sequence: sum to 5050, spawned true.

**Live:** `make interview` beat `s1-sum.1`. Evidence is `allow R-ALLOW spawned=True` and stdout `5050`.

---

## 2. Blocked path (90 seconds)

**Say:** "This is the other sequence. `import os` dies in the AST gate. `spawned` is false. The preview says a raw interpreter would have run it. We do not run it."

**Show:** the blocked-escape sequence. Then the UI traversal and import scenarios.

**Live:**

* `s4-traversal.1` — `R-PATH-TRAVERSAL`, spawned false.
* `s5-import.1` — `R-IMPORT-HARD-DENY`, spawned false.
* `interview.preview-not-executed` — `executed` is false.
* `interview.os-not-grantable` — the allowlist contains `os` and the rule is still `R-IMPORT-HARD-DENY`.

**Say:** "That last one is the design. Hard denials are not YAML switches. I can put `os` in the allowlist and the guard still refuses."

---

## 3. STRIDE, one breath each (90 seconds)

Use the table in `docs/threat-model.md`.

* **Spoofing.** `Python` and `send_email` are unknown tools, not aliases.
* **Tampering.** `..` and symlinks are refused. `interview.symlink` is `R-PATH-SYMLINK`. An edited audit line fails verify: `interview.audit-tamper`, `reason=hash`.
* **Repudiation.** Every call is a chained record. `audit-verify` reports `events=9 ok=True` before the tamper beat.
* **Information disclosure.** The file tools never open the refused path. A snippet has no `open`. If I grant `pathlib` anyway, `Path.read_text` still hits `R-SANDBOX-OPEN`. The audit stores a hash and a short redacted preview.
* **Denial of service.** `s7-wall.1` is `R-LIMIT-WALL`. The corpus also locks output size and a memory cap.
* **Elevation.** No shell executor. `s6-shell.1` is `R-TOOL-NO-EXECUTOR` even if the YAML flag is on.

---

## 4. Decisions (60 seconds)

Read the decisions table, not the whole ADR folder.

* Subprocess instead of Docker as the default, because the tests have to run without a daemon. The residual risk is a same-user process. I would add a sandbox user in production under this policy, not instead of it.
* Preview instead of executing the bad call.
* Regression gate instead of hoping a reviewer notices a soft allow.

**Live:** `s8-regression.gate` is `gate_ok=False` for `prot-import-pathlib` and `prot-code-size`. `s8-regression.os-hard-deny` stays deny.

---

## 5. What I would not claim (30 seconds)

**Say:** "This is not a hypervisor. The audit hook is not a network namespace. The HMAC key in the demo is a public placeholder, so tamper evidence here assumes the key is not sitting next to the log. `make eval` is 55 of 55 on a development corpus, which means the gate holds, not that I have measured unknown attacks."

Point at `FAILURE_MODES.md` if they ask what breaks.
