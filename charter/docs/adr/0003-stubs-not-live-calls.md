# ADR 0003: Aegis-shaped and Lens-shaped stubs, no imports

* Status: accepted
* Date: 2026-11-10

## Context

The pack is only interesting if it is about the same platform. Aegis already has an audit vocabulary: `prompt_received`, `dlp_redaction`, `routing_decision`, `request_blocked`, `llm_call`, `tool_call`, `tool_call_blocked`, `auth_failed`, routes `allow` / `redact_and_continue` / `local_only` / `block` / `require_approval`, labels `PUBLIC` through `RESTRICTED`, and an HMAC chain over a fixed field list with the previous hash prepended.

Lens already has four objectives and three statuses: availability, latency, quality, safety; `within_budget`, `ticket`, `page`. The targets in `eval/slo.yaml` are 0.995, 0.99, 0.95, and 0.999.

Charter could import those packages and call them. Then the demo would not run from `charter/` alone, and a private helper in Aegis would become Charter's API the moment we used it.

## Decision

Charter does not import Aegis or Lens.

`fixtures/aegis_audit.jsonl` is generated by `charter/ingest/aegis.py`. The hashed fields and the HMAC construction match Aegis's audit store. The chain key is the published demo constant `charter-demo-not-a-secret`. It is not Aegis's key and it is not a secret. Details carry join fields Aegis's table does not have as columns: `data_residency`, `region`, `model`. Those are the exporter's job. The event types, routes, labels, and chain are the vocabulary.

`fixtures/lens_slo.json` carries the four ids, the four targets, and a status. Load fails if a target is not the contract constant copied into `charter/config.py`. Charter does not recompute burn. Quality is `page` and safety is `ticket` on purpose.

A test rebuilds the audit log from the generator and compares bytes, and a test flips one outcome and expects the chain to fail.

## Consequences

Good:

* `make test` does not start Aegis or Lens and does not need their dependencies.
* The contract is explicit. Drift shows up as a failed load or a failed byte compare, not as a wrong green cell.
* The README can say "shaped like" without pretending the HTTP call exists.

Bad:

* A real Aegis export that uses different detail keys will not light EU-10 until the adapter is updated. The adapter is the violation function, and it is small on purpose.
* The demo key would be embarrassing if someone pointed it at a real log. The fixture writer is the only producer. Production verification would take the key from a secret store and would not have a default.
* The Lens numbers are not Lens's measured SLIs. They are a snapshot with Lens's targets and Lens's status words. Quoting them as Lens's production quality would be false. The pack's note says they are a stand-in.

## Alternatives

* HTTP to localhost ports 8080 and 8088. Rejected. The demo would be red whenever those processes are down, which is the normal case.
* Copying Python modules out of the siblings. Rejected. That is an import with extra steps, and it rots.
* A free-form JSON "audit" with our own field names. Rejected. The point of the stub is that a reviewer who knows Aegis recognizes it.
